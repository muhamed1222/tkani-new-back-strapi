# ✅ Исправление уязвимостей nodemailer

## Проблема

**Уязвимости**:
1. **Email может быть отправлен на непреднамеренный домен** (GHSA-mm7p-fcc7-pg87, CVE-2025-13033)
   - Версии <7.0.7 неправильно обрабатывают quoted local-parts с символом '@'
   - Может привести к отправке email на непреднамеренные домены

2. **DoS через рекурсивные вызовы** (GHSA-rcmh-qjqh-p98v)
   - Версии <7.0.11 уязвимы к DoS через неограниченную рекурсию в addressparser
   - Может привести к падению приложения при обработке глубоко вложенных групп

**Пакет**: `nodemailer` версии <=7.0.10  
**Серьезность**: Moderate

## Решение

Применено три уровня защиты:

### 1. Обновление nodemailer до безопасной версии

Использован механизм `overrides` в `package.json` и обновлена прямая зависимость для принудительного обновления `nodemailer` до версии `7.0.11+`.

```json
{
  "dependencies": {
    "nodemailer": "^7.0.11"
  },
  "overrides": {
    "@strapi/provider-email-nodemailer": {
      "nodemailer": "^7.0.11"
    },
    "nodemailer": "^7.0.11"
  }
}
```

### 2. Middleware для валидации email и rate limiting

Создан кастомный middleware `email-security.js`, который:

- ✅ **Валидирует email адреса**: Строгая проверка формата и домена перед отправкой
- ✅ **Блокирует опасные паттерны**: Защита от обхода валидации через специальные символы
- ✅ **Rate limiting**: Ограничение количества email запросов (5 в минуту с одного IP)
- ✅ **Проверка доменов**: Валидация доменной части email адреса
- ✅ **Логирование**: Записывает в лог попытки отправки невалидных email

### 3. Валидация в Email Service

Обновлен `src/services/email.js` для валидации email адресов перед отправкой:

- ✅ Проверка формата email
- ✅ Проверка на опасные символы
- ✅ Проверка длины
- ✅ Валидация домена
- ✅ Блокировка подозрительных доменов (localhost, 127.0.0.1 и т.д.)

## Правила валидации email

### Разрешенные паттерны:
- Стандартный формат: `user@domain.com`
- Длина до 254 символов
- Валидный домен с TLD

### Блокируемые паттерны:
- Множественные `@` символы
- Двойные точки `..`
- Пробелы
- Угловые скобки `<>`
- Кавычки `"'`
- Подозрительные домены (localhost, 127.0.0.1)

## Rate Limiting

- **Лимит**: 5 email запросов в минуту с одного IP
- **Окно**: 60 секунд
- **Действие при превышении**: HTTP 429 (Too Many Requests)

## Настройка для production

1. **Настройте rate limiting** в `email-security.js`:
   ```javascript
   const MAX_EMAILS_PER_WINDOW = 10; // Увеличьте для production
   ```

2. **Используйте email сервисы с защитой**:
   - SendGrid, Mailgun, AWS SES и т.д.
   - Они имеют встроенную защиту от спама и валидацию

3. **Мониторинг**:
   - Следите за логами попыток отправки невалидных email
   - Настройте алерты на подозрительную активность

4. **Дополнительная защита**:
   - Используйте CAPTCHA для форм отправки email
   - Валидируйте email на клиентской стороне перед отправкой
