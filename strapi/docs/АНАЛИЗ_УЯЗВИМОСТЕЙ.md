#### 4. Использование reverse proxy (nginx)

**Рекомендуется**: Использовать nginx как reverse proxy перед Strapi для дополнительной безопасности, rate limiting и SSL/TLS.

**Пример конфигурации для `/etc/nginx/sites-available/centertkani-api`:**

```nginx
# Rate limiting зона (определить в http блоке nginx.conf)
# limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;

# Редирект HTTP -> HTTPS
server {
    listen 80;
    listen [::]:80;
    server_name api.centertkani.ru;
    
    # Редирект на HTTPS
    return 301 https://$server_name$request_uri;
}

# HTTPS конфигурация
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name api.centertkani.ru;

    # SSL сертификаты (Let's Encrypt)
    ssl_certificate /etc/letsencrypt/live/api.centertkani.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.centertkani.ru/privkey.pem;
    
    # SSL настройки безопасности
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    # Заголовки безопасности
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # Rate limiting
    limit_req zone=api_limit burst=20 nodelay;
    limit_req_status 429;

    # Логирование
    access_log /var/log/nginx/api.centertkani.ru.access.log;
    error_log /var/log/nginx/api.centertkani.ru.error.log;

    # Максимальный размер тела запроса (для загрузки файлов)
    client_max_body_size 50M;
    client_body_buffer_size 128k;

    # Проксирование на Strapi
    location / {
        proxy_pass http://127.0.0.1:1337;
        proxy_http_version 1.1;
        
        # WebSocket поддержка
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        
        # Заголовки для корректной работы
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Port $server_port;
        
        # Таймауты
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
        
        # Кэширование
        proxy_cache_bypass $http_upgrade;
        proxy_no_cache $http_upgrade;
    }

    # Запрет доступа к скрытым файлам
    location ~ /\. {
        deny all;
        access_log off;
        log_not_found off;
    }
}
```

#### 7. Мониторинг и логирование

**Статус**: ✅ Sentry настроен в middleware `global::sentry`. Все security middleware логируют блокированные запросы.

**Что уже логируется:**

| Middleware | События логирования |
|------------|---------------------|
| `redirect-security` | Блокированные небезопасные редиректы |
| `file-validation` | Блокированные загрузки файлов (неверный тип/MIME/расширение) |
| `dev-server-security` | Блокированные запросы к dev серверу с неверным Origin |
| `email-security` | Превышение rate limit для email, блокированные невалидные email адреса |
| `sentry` | Все ошибки приложения с контекстом запроса |

**Настройка для production:**

1. **Настройка Sentry в `.env`:**
```env
SENTRY_DSN=https://your-dsn@sentry.io/project-id
NODE_ENV=production
```

2. **Проверка работы Sentry:**
   - Убедитесь, что `SENTRY_DSN` установлен (проверьте логи: `Sentry middleware initialized`)
   - Проверьте отправку ошибок в Sentry dashboard

3. **Настройка алертов в Sentry:**
   - ✅ Критические ошибки (500, необработанные исключения)
   - ✅ Множественные блокировки с одного IP (возможная атака)
   - ✅ Превышение rate limit для email
   - ✅ Блокированные загрузки файлов

**Мониторинг логов:**

**Локальные логи (development):**
```bash
# Просмотр логов Strapi
npm run develop 2>&1 | grep -E "(warn|error|Blocked)"

# Фильтрация security событий
npm run develop 2>&1 | grep -E "Blocked|rate limit|invalid"
```

**Production логи:**
- Используйте `pm2 logs` или `systemd journalctl` для просмотра логов
- Настройте ротацию логов (logrotate)
- Отправляйте логи в централизованную систему (ELK, Grafana Loki)

**Рекомендации:**

✅ **Обязательно:**
- Настройте Sentry алерты на email/Slack для критических ошибок
- Регулярно проверяйте логи на подозрительную активность
- Мониторьте количество блокированных запросов

⚠️ **Опционально:**
- Интеграция с внешними системами мониторинга (Datadog, New Relic)
- Настройка дашбордов для визуализации метрик безопасности
- Автоматический анализ паттернов атак
