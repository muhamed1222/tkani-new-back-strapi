# ✅ Исправление уязвимости esbuild (Development Server)

## Проблема

**Уязвимость**: Development server уязвим к запросам с любого сайта (CVE-2025-22871, GHSA-67mh-4wv8-2f99)  
**Пакет**: `esbuild` версии <=0.24.2 (через `vite`)  
**Серьезность**: Moderate  
**Описание**: Уязвимость позволяет любому сайту отправлять запросы к development серверу и читать ответы из-за разрешительных настроек CORS.

**Важно**: Эта уязвимость затрагивает **только development режим**. В production режиме (`npm run build` + `npm run start`) она не актуальна.

## Решение

Применено два уровня защиты:

### 1. Обновление esbuild до безопасной версии

Использован механизм `overrides` в `package.json` для принудительного обновления `esbuild` до версии `0.25.0+`.

```json
{
  "overrides": {
    "vite": {
      "esbuild": "^0.25.0"
    },
    "esbuild": "^0.25.0"
  }
}
```

### 2. Middleware для защиты development сервера

Создан кастомный middleware `dev-server-security.js`, который:

- ✅ **Проверяет Origin**: Валидирует источник запроса в development режиме
- ✅ **Блокирует неразрешенные источники**: Отклоняет запросы от неразрешенных доменов
- ✅ **Устанавливает строгие CORS**: Настраивает правильные CORS заголовки
- ✅ **Защищает preflight запросы**: Блокирует OPTIONS запросы от неразрешенных источников
- ✅ **Логирует попытки**: Записывает в лог попытки доступа от неразрешенных источников
- ✅ **Работает только в development**: Не влияет на production режим

## Разрешенные источники для development

Middleware проверяет запросы на соответствие списку разрешенных источников:

- `http://localhost:1337` (Strapi)
- `http://localhost:5173` (Vite dev server)
- `http://localhost:5174`, `http://localhost:5175` (дополнительные порты)
- `http://localhost:3000` (альтернативный порт)
- `http://127.0.0.1:1337`, `http://127.0.0.1:5173` (IP адреса)

**Важно**: Для добавления новых источников обновите массив `allowedOrigins` в `src/middlewares/dev-server-security.js`.

## Важные рекомендации

### Для development:

1. ✅ **Не открывайте development сервер в публичной сети**
2. ✅ **Используйте только localhost** для доступа к development серверу
3. ✅ **Не используйте `0.0.0.0`** в качестве host в development (используйте `localhost`)
4. ✅ **Используйте VPN или SSH туннель** для удаленного доступа

### Для production:

1. ✅ **Всегда используйте production режим**: `npm run build` + `npm run start`
2. ✅ **Используйте reverse proxy** (nginx) для дополнительной защиты
3. ✅ **Настройте firewall** для ограничения доступа
4. ✅ **Используйте HTTPS** для всех соединений

### Настройка для удаленной разработки:

Если вам нужен доступ к development серверу извне:

1. **Используйте SSH туннель**:
   ```bash
   ssh -L 1337:localhost:1337 user@server
   ```

2. **Или используйте VPN** для безопасного доступа

3. **Не открывайте порты напрямую** в firewall
